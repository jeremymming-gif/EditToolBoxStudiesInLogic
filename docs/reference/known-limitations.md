# 已知限制与绕行

适用版本：**v1.5.0**（Flet 单壳首发；2026-11 起）。只列当前版本仍存在的限制，已修复项不入表。
本页随版本维护，与 GitHub Release 正文「如实说明」同源。

## 平台与界面（Flet 单壳）

| 限制 | 症状 | 影响 | 绕行 | 目标版本 |
|---|---|---|---|---|
| 系统拖放不可用 | 从资源管理器/访达把文件拖到窗口无反应（Flet/Flutter 桌面端未暴露外部拖放 API，已实测记录） | 选文件要走对话框 | 点「浏览…」打开 Windows 原生对话框，或把路径粘贴进输入框 | 待 Flet 上游支持 / P4 评估 pywin32 旁路 |
| IME 候选窗 | 中文输入本身可用（已实测 Unicode 输入 17 字符无误），但候选窗位置/跟随未做自动化验证 | 个别输入场景观感不同 | 先确认系统输入法状态；异常时附截图反馈 | 待人工真机复核 |
| onefile 冷启动偏慢 | 首次启动约 **4.4–4.6s**（二次约 2.4s），因 onefile 需解压运行时 | 首次体验略慢 | 无（可接受）；后续可评估 onedir 分发 | 观察 |
| 安装包体积 | Windows zip 约 **75–85MiB**、macOS 包同量级（含 Flet 运行时与引擎） | 下载体积较大 | 网络慢时用支持断点的下载工具 | 无（预期） |
| 未签名 / 未公证 | Windows SmartScreen「Windows 已保护你的电脑」；macOS「已损坏，无法打开」 | 首次打开多一步 | Windows「更多信息 → 仍要运行」；macOS 右键→打开 或 `xattr -dr com.apple.quarantine` | 无（2026-10-16 定案不签名） |
| macOS 仅 CI 验证 | 本机为 Windows；mac 构建/运行由 CI macos runner 验证 | mac 侧缺少人工真机走查 | 发版前在 mac 上按 `FIRST-OPEN-macOS.txt` 走一遍关键路径 | 发版流程固定项 |
| Windows 平台覆盖 | 真机冒烟只在发版前各做一次 | 平台长尾风险 | 每次发版前按 `windows-smoke-checklist.md` 逐项走、留回执；pytest 常跑 | 发版流程固定项 |
| 引用库写库（P6） | Flet 版「待处理」只含字段冲突与版本库状态区；库健康 / 已处理两段仍只在 macOS 版，也没有「手动补提交」按钮 | 三段合一的处理中心与手动补提交在 Flet 上不可用 | 库健康用 `Engine/bibdb.py lint --with-records`，已处理用 `report`；提交由写库成功后的自动本地 commit 完成（入藏与待裁决都有） | 后续版本 |
| 设置项取舍 | Flet 版设置页聚焦外观/路径/日志/环境检查；旧 Tk 版的 AI 配置页未迁移 | 需要 AI 核实时走 CLI | `Engine/convert.py --verify-refs` 等 CLI 参数（见 `Engine/docs/ENGINE_API.md`） | 后续版本 |

## 引擎与版面（沿用）

| 限制 | 症状 | 影响 | 绕行 | 目标版本 |
|---|---|---|---|---|
| 个别案例附录字号（86-05） | 引擎按默认字号排版；人工附录为 9pt，该稿 28 页 vs 人工 26 页 | 个别案例的版式差，不算缺陷 | 需要 9pt 时在 tex 附录前用 `\zihao{-5}`，全文末用 `\zihao{5}` 复位 | 无（体例项；可选开关待编辑部确认） |
| 验收判据与人工口径差异 | 3 项验收口径差异：86-10 判据误报；88-01/88-02 注内引用 `\parencite` 与人工 page-locator 不同 | 验收报告出现错误的优先级归类 | 按报告中的归因说明阅读；不改判据（不对单条加严） | 待编辑部拍板（改判据需另走版本） |
| 参考文献源清单计数误报 | 源清单覆盖/引用计数类误报（如标题 `\textup{}`、引号归一化） | 仅报告噪声；产物 bib 齐全 | 忽略该 finding、以 bib 条目与人工核对为准 | 下一版本（开发主线已修复） |
| Word 英文标题页 | 英文稿标题页版式与人工版有差异 | 轻微版式差异，信息项 | 人工后期微调；不视为缺陷 | 待专项（优先级低） |
| LibreOffice 条件必需 | 未安装时合并 PDF / 导出原稿 PDF 降级并给出 warning | 仅这两个功能；初排转换不受影响 | 安装 LibreOffice，或按提示路径处理 | 无（已文档化） |
| 模板/连接号默认行为变化 | 与 1.4.0 产物不同（ZH-08 默认启用、模板 88 版式） | 交付稿版式变化 | 如需 1.4.0 旧行为，可用既有开关回退 | 无（预期行为） |
| 目录生成字体检查 | `fontset=windows` 前置检查会因缺字体中止（设计如此） | 无字体环境不能生成目录 | 安装字体，或按提示处理 | 无 |
| 大期合并内存 | 整期合并 PDF 大文件时内存占用高（历史观察） | 极端期可能较慢 | 分批合并，或加大内存 | 待观察 |

## 反馈与更新

发现未列入的限制、或绕行办法不适用：请到 GitHub Issues 反馈（附版本号与复现步骤）。
本页随版本更新；历史版本的「已知问题」以对应 Release 正文为准。

## 失败诊断的边界

- Flet 单壳的失败信息分三层：**结果横幅**（可读原因 + 产物路径）、**日志区摘要层**（可切「只看摘要」）、
  **原始输出**（引擎末行契约与退出码）；不再有旧 Tk 版的「诊断卡/诊断包」。
- **设置 → 环境检查**只调用 `Engine/envcheck.py --json`（只读）：TeX / biber / LibreOffice / 字体 / 磁盘；
  不改系统、不上传。
- 引擎退出码语义不变：`proofcheck` / `checkbib` 的 1 = **有命中项，不是失败**；`toc` 的 1 = 已完成但需人工核对。
- 缺 `xelatex`/`biber` 等属工具缺失，按提示补装后重跑；诊断信息只在本机生成。
