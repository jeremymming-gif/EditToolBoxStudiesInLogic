# 已知限制与绕行

适用版本：**v1.7.0**（Flet 单壳）。只列当前版本仍存在的限制，已修复项不入表。
本页随版本维护，与 GitHub Release 正文「如实说明」同源。

## 平台与界面（Flet 单壳）

| 限制 | 症状 | 影响 | 绕行 | 目标版本 |
|---|---|---|---|---|
| 系统拖放不可用 | 从资源管理器/访达把文件拖到窗口无反应（Flet/Flutter 桌面端未暴露外部拖放 API，已实测记录） | 选文件要走对话框 | 点「浏览…」打开 Windows 原生对话框，或把路径粘贴进输入框 | 待 Flet 上游支持 / P4 评估 pywin32 旁路 |
| IME 候选窗 | 中文输入本身可用（已实测 Unicode 输入 17 字符无误），但候选窗位置/跟随未做自动化验证 | 个别输入场景观感不同 | 先确认系统输入法状态；异常时附截图反馈 | 待人工真机复核 |
| onefile 冷启动偏慢 | 每次启动解包 ~77MB 单文件运行时（暖机约 4s）；首启另需解压 Flet 桌面客户端（约 135MB，慢盘 30–60s） | 启动等待明显、首启更久 | 1.6.1 起首启弹系统通知提示等待，并写启动日志便于定位；二次启动正常 | 观察 / 评估分发形态 |
| 安装包体积 | Windows zip 约 **75–85MiB**、macOS 包同量级（含 Flet 运行时与引擎） | 下载体积较大 | 网络慢时用支持断点的下载工具 | 无（预期） |
| 首启窗口延迟（已缓解） | 打包形态首启要解压 Flet 客户端，窗口出现前可能只有 Dock 图标、鼠标转圈 | 易被误认为「没启动」而重复点击 | 1.6.1 起：首启系统通知提示 + 启动诊断日志；建议下载后首次启动耐心等待，避免重复双击 | 已缓解 |
| 未签名 / 未公证 | Windows SmartScreen「Windows 已保护你的电脑」；macOS「已损坏，无法打开」 | 首次打开多一步 | Windows「更多信息 → 仍要运行」；macOS 右键→打开 或 `xattr -dr com.apple.quarantine` | 无（已定案不签名） |
| Windows 真机验证 | 批 112 起维护机为 macOS：GUI 与引擎已在 mac 真机逐页验证；Windows 侧由 CI windows runner + 发版前冒烟覆盖 | Windows 长尾（DWM 深色标题栏 / 托盘 / 多 DPI / IME）缺少逐批人工走查 | 发版前按 `windows-smoke-checklist.md` 逐项走并留回执；`pytest` 常跑 | 发版流程固定项 |
| Windows 平台覆盖 | 真机冒烟只在发版前各做一次 | 平台长尾风险 | 每次发版前按 `windows-smoke-checklist.md` 逐项走、留回执；pytest 常跑 | 发版流程固定项 |
| 引用库写库 | Flet 版「待处理」含字段冲突与版本库状态区；另有「编辑 / 查重合并 / 字段归位 / 库健康」四个视图（含批量裁决 dry-run 预览与已处理留痕），「设置」页补上核实成本闸门（核实上限 / 先算账 / 全量核实 / 先查库，存 `settings.bibdb` 段）。仍缺：从「查库结果 / 待裁决 / 入藏结果」一键跳到编辑器的深链（目前只能在「编辑」视图按 key 打开） | 深链要手动抄 key；其余写库能力已可用 | 库健康也可用 `Engine/bibdb.py lint --with-records`，已处理用 `report`；核实成本闸门也可用 CLI（`--verify-plan` / `--verify-max`） | 后续版本（深链需改 `bib_advanced.py` / `bib_write.py`） |
| 引用库核实上限与 AI 面板 | 走 AI 直连核实链路时，`services/engine_bridge.py` 的 `ai_verify_call` 会用 AI 面板的「单篇核实条数」覆盖 `settings.bibdb` 的 `verify_max`（`verify_plan` / `verify_all_refs` / `lookup_enabled` 仍透传） | 两个上限同时存在时以 AI 面板为准 | 需要引用库上限生效时：把 AI 面板的「单篇核实条数」设为同值，或走非 AI 设值/CLI | 后续版本（需统一两处预算键） |
| 查重候选与 sidecar | 「查重合并」把 `report-duplicates` 的产物写到**临时目录**（读完即删，不写笔记仓）；同页「确认非重复」调用 `ack-duplicates`，只写库目录旁的 `health-ignore.json`（不改库、不自动提交，`git status` 会显示该未跟踪文件） | 需要把 sidecar 纳入版本管理时得手动提交 | 需要留档时在笔记仓手动 `git add bib_db/health-ignore.json` 并提交；重新审计仍会列出全部候选（引擎设计如此） | 无（引擎既有语义） |
| AI 全文直连核查 | Flet 面板只做「文献元数据直连核实」与「两段式任务书」；`--llm-fulltext`（正文分片直连 + 自动应用）没有界面入口 | 需要全文直连核查时只能走 CLI | `Engine/convert.py --verify-refs --llm-fulltext …`（见 `Engine/docs/ENGINE_API.md`），同样受预算闸约束 | 后续版本 |
| 参考文献规范化页的「并回」 | 图形壳已移除并回入口（为防覆盖正文），页内只做离线体检；「重新编译该篇」也未复刻（单壳不写文档逻辑，编译走「编译全部」），入藏走引用库页既有入口 | 交回 bib 的并回与重编需命令行 | `Engine/checkbib.py --returned … --merge-into <产物>/reference.bib --out …`（并回前自动备份 `.ai前`）；重编按四步 xelatex → biber → xelatex ×2 | 后续版本（并回需先解决覆盖正文风险） |
| 内容模板页「生成并交付」默认 | 内容模板 tab 尚未迁到 Flet（属整期装配页），「生成目录」步骤仍默认「仅生成 tex」（安全默认，保留） | 出成品目录要先手动改选项 | 生成目录步骤取消勾选「仅生成 tex」，一次出中英文目录与 PDF | 后续版本（随内容模板页迁移恢复「生成并交付」默认） |
| 元数据表单的边界 | 英文关键词两个模板都没有槽位（引擎日志提示人工放置）；责编仍是自由文本，未接 `convert.py --list-editors` 下拉 | 填了英文关键词不会自动落版；责编名要手打 | 英文关键词人工放置；责编按引擎可识别的写法填，名单可用 CLI `--list-editors` 查 | 后续版本 |


## 引擎与版面（沿用）

| 限制 | 症状 | 影响 | 绕行 | 目标版本 |
|---|---|---|---|---|
| 个别案例附录字号（86-05） | 引擎按默认字号排版；人工附录为 9pt，该稿 28 页 vs 人工 26 页 | 个别案例的版式差，不算缺陷 | 需要 9pt 时在 tex 附录前用 `\zihao{-5}`，全文末用 `\zihao{5}` 复位 | 无（体例项；可选开关待编辑部确认） |
| 规则提示与人工判读的差异 | 少数稿件会出现规则误报，或注内页引的写法与人工习惯不同 | 报告中的优先级归类可能与人工判断有偏差 | 按报告中的归因说明阅读，逐条人工判断；不因单篇加严规则 | 待编辑部确认（改判据需另走版本） |
| 参考文献源清单计数误报 | 源清单覆盖/引用计数类误报（如标题 `\textup{}`、引号归一化） | 仅报告噪声；产物 bib 齐全 | 忽略该 finding、以 bib 条目与人工核对为准 | 下一版本（开发主线已修复） |
| Word 英文标题页 | 英文稿标题页版式与人工版有差异 | 轻微版式差异，信息项 | 人工后期微调；不视为缺陷 | 待专项（优先级低） |
| LibreOffice 条件必需 | 未安装时合并 PDF / 导出原稿 PDF 降级并给出 warning | 仅这两个功能；初排转换不受影响 | 安装 LibreOffice，或按提示路径处理 | 无（已文档化） |
| 模板/连接号默认行为变化 | 与 1.4.0 产物不同（ZH-08 默认启用、模板 88 版式） | 交付稿版式变化 | 如需 1.4.0 旧行为，可用既有开关回退 | 无（预期行为） |
| 目录生成字体检查 | `fontset=windows` 前置检查会因缺字体中止（设计如此） | 无字体环境不能生成目录 | 安装字体，或按提示处理 | 无 |
| 大期合并内存 | 整期合并 PDF 大文件时内存占用高（历史观察） | 极端期可能较慢 | 分批合并，或加大内存 | 待观察 |

## 反馈与更新

发现未列入的限制、或绕行办法不适用：请到 GitHub Issues 反馈（附版本号与复现步骤）。
本页随版本更新；历史版本的「已知问题」以对应 Release 正文为准。

## 失败诊断的边界

- Flet 单壳的失败信息分三层：**结果横幅**（可读原因 + 产物路径）、**日志区摘要层**（可切「只看摘要」）、
  **原始输出**（引擎末行契约与退出码）；复现问题用「设置 → 诊断包」导出或复制诊断信息（已脱敏，不含 API Key/正文）。
- **设置 → 环境检查**只调用 `Engine/envcheck.py --json`（只读）：TeX / biber / LibreOffice / 字体 / 磁盘；
  不改系统、不上传。
- 引擎退出码语义不变：`proofcheck` / `checkbib` 的 1 = **有命中项，不是失败**；`toc` 的 1 = 已完成但需人工核对。
- 缺 `xelatex`/`biber` 等属工具缺失，按提示补装后重跑；诊断信息只在本机生成。
