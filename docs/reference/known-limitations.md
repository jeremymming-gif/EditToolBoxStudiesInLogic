# 已知限制与绕行

本页随当前正式版维护。发布版本见 [GitHub 最新发布](https://github.com/jeremymming-gif/EditToolBoxStudiesInLogic/releases/latest)。

## 平台与界面（Flet 单壳）

| 限制 | 症状 | 影响 | 绕行 | 目标版本 |
|---|---|---|---|---|
| 系统拖放不可用 | 从资源管理器/访达把文件拖到窗口无反应（Flet/Flutter 桌面端未暴露外部拖放 API，已实测记录） | 选文件要走对话框 | 点「浏览…」打开 Windows 原生对话框，或把路径粘贴进输入框 | 待 Flet 上游支持 / P4 评估 pywin32 旁路 |
| IME 候选窗 | 中文输入本身可用（已实测 Unicode 输入 17 字符无误），但候选窗位置/跟随未做自动化验证 | 个别输入场景观感不同 | 先确认系统输入法状态；异常时附截图反馈 | 待人工真机复核 |
| 启动等待 | 单文件应用需要解包运行环境。Windows 首次启动还可能要准备 Flet 桌面客户端，macOS 包已附带客户端 | 首次启动可能要等一会儿才显示窗口 | 等待窗口出现，避免重复双击。若迟迟没有窗口，可附启动日志反馈 | 观察 |
| 安装包体积 | 压缩包内含应用运行环境及引擎，macOS 包还含 Flet 桌面客户端 | macOS 包下载时间通常较长 | 下载页会显示各包大小 | 无 |
| 首次打开提示 | Windows 可能出现 SmartScreen「Windows 已保护你的电脑」。macOS 包未公证，首次打开可能被系统拦截 | 首次打开需要核对来源 | Windows 从正式下载页获取后可点「更多信息 → 仍要运行」。macOS 按 [安装指南](../guide/install.md#macos) 操作，若仍无法打开，请反馈包版本、macOS 版本和具体报错 | 无 |
| Windows 桌面验证 | 自动测试覆盖部分界面和引擎逻辑 | 托盘、不同缩放比例、中文输入法等行为还需在实际桌面确认 | 遇到异常请附版本、显示缩放及复现步骤反馈 | 待实机验证 |
| 引用库版本与同步 | 「引用库 → 版本与同步」显示目标库、Git 状态、ahead/behind、冲突状态及最近库提交；提供显式确认的提交、推送和回退到上一个库版本操作 | 页面不展示 diff，也不提供 pull、fetch、冲突解决或自动同步；冲突、merge 或 rebase 状态下版本操作不可用 | 先刷新状态并核对目标库；需要查看差异或处理远端冲突时，使用熟悉的 Git 工具并谨慎操作 | 当前版本 |
| AI 初排的核实范围提示 | 两段式 AI 初排按任务书列出的正文引用范围显示预计委派条数；Chat 复制和 API 发送共用固定 120 条上限，未知条数时界面会阻止这两步。API 发送前检查单篇和批次 token 预算 | Chat 任务书供用户交给外部工具，外部费用由该服务决定。API 的 token 用量是估算，金额以服务商账单为准 | 缩小本次正文引用范围，或按需调整「设置 → AI」中的 token 预算；不要把估算当成实际费用 | 当前版本 |
| 查重候选与 sidecar | 「查重合并」把 `report-duplicates` 的产物写到**临时目录**（读完即删，不写笔记仓）；同页「确认非重复」调用 `ack-duplicates`，只写库目录旁的 `health-ignore.json`（不改库、不自动提交，`git status` 会显示该未跟踪文件） | 需要把 sidecar 纳入版本管理时得手动提交 | 需要留档时在笔记仓手动 `git add bib_db/health-ignore.json` 并提交；重新审计仍会列出全部候选（引擎设计如此） | 无（引擎既有语义） |
| AI 全文直连核查 | Flet 面板只做「文献元数据直连核实」与「两段式任务书」；`--llm-fulltext`（正文分片直连 + 自动应用）没有界面入口 | 需要全文直连核查时只能走 CLI | `Engine/convert.py --verify-refs --llm-fulltext …`（见 `Engine/docs/ENGINE_API.md`），同样受预算闸约束 | 后续版本 |
| 参考文献规范化页的「并回」 | 图形壳已移除并回入口（为防覆盖正文），页内只做离线体检；「重新编译该篇」也未复刻（单壳不写文档逻辑，编译走「编译全部」），入藏走引用库页既有入口 | 交回 bib 的并回与重编需命令行 | `Engine/checkbib.py --returned … --merge-into <产物>/reference.bib --out …`（并回前自动备份 `.ai前`）；重编按四步 xelatex → biber → xelatex ×2 | 后续版本（并回需先解决覆盖正文风险） |
| 内容模板页「生成并交付」默认 | 内容模板 tab 尚未迁到 Flet（属整期装配页），「生成目录」步骤仍默认「仅生成 tex」（安全默认，保留） | 出成品目录要先手动改选项 | 生成目录步骤取消勾选「仅生成 tex」，一次出中英文目录与 PDF | 后续版本（随内容模板页迁移恢复「生成并交付」默认） |
| 元数据表单的边界 | 英文关键词两个模板都没有槽位（引擎日志提示人工放置）；责编仍是自由文本，未接 `convert.py --list-editors` 下拉 | 填了英文关键词不会自动落版；责编名要手打 | 英文关键词人工放置；责编按引擎可识别的写法填，名单可用 CLI `--list-editors` 查 | 后续版本 |
| 运行中次级页面的内部入口 | 运行中切换部分次级页面、或触发引用库归一/合放等页面内部按钮时，仍可能静默无响应 | 少数入口「点了没反应」，易被误认为卡死 | 等当前任务结束（或点「停止」）后再操作 | 后续版本（内部按钮的可见拒绝待后续包处理） |


## 引擎与版面（沿用）

| 限制 | 症状 | 影响 | 绕行 | 目标版本 |
|---|---|---|---|---|
| 个别案例附录字号（86-05） | 引擎按默认字号排版；人工附录为 9pt，该稿 28 页 vs 人工 26 页 | 个别案例的版式差，不算缺陷 | 需要 9pt 时在 tex 附录前用 `\zihao{-5}`，全文末用 `\zihao{5}` 复位 | 无（体例项；可选开关待编辑部确认） |
| 规则提示与人工判读的差异 | 少数稿件会出现规则误报，或注内页引的写法与人工习惯不同 | 报告中的优先级归类可能与人工判断有偏差 | 按报告中的归因说明阅读，逐条人工判断；不因单篇加严规则 | 待编辑部确认（改判据需另走版本） |
| 参考文献源清单计数误报 | 源清单覆盖/引用计数类误报（如标题 `\textup{}`、引号归一化） | 仅报告噪声；产物 bib 齐全 | 忽略该 finding、以 bib 条目与人工核对为准 | 下一版本（开发主线已修复） |
| Word 英文标题页 | 英文稿标题页版式与人工版有差异 | 轻微版式差异，信息项 | 人工后期微调；不视为缺陷 | 待专项（优先级低） |
| LibreOffice 条件必需 | 未安装时合并 PDF / 导出原稿 PDF 降级并给出 warning | 仅这两个功能；初排转换不受影响 | 安装 LibreOffice，或按提示路径处理 | 无（已文档化） |
| 模板/连接号默认行为变化 | 与 1.4.0 产物不同（ZH-08 默认启用、模板 88 版式） | 交付稿版式变化 | 如需 1.4.0 旧行为，可用既有开关回退 | 无（预期行为） |
| 目录生成字体检查 | `fontset=windows` 前置检查会因缺字体中止（设计如此） | 无字体环境不能生成目录 | 安装字体，或按提示处理 | 无 |
| 参考文献排序 locale（biber/CLDR） | 本机 biber 的 CLDR 数据缺中文拼音 tailoring 时，biber 仍退出 0、`.bbl` 也非空，只在 `.blg` 写 `No sort tailoring available for locale '…'`，中文条目按西文默认顺序排 | 排序是错的、PDF 看起来却「编译成功」；`--compile`（含「编译全部」）会判**硬失败**并删掉本次 PDF，环境检查的 biber 项也会红（退出码 2） | 装带完整 CLDR 的 TeX 发行版或升级 biber（2.21 实测 `biber -l=zh_pinyin` 打印单下划线，`.bcf` 的双下划线 `zh__pinyin` 两种都认）；先在「设置 → 环境检查」确认 biber 项为绿 | 无（引擎已改为硬失败，不再出假 PDF） |
| 旧版内容模板（缺 `sortlocale=zh__pinyin` 标记） | 目录/篇目模板是旧版（`SLCN-MIX.sty` 没有该标记）时，中文目录排序仍按西文 | 只影响目录拼音排序 | 环境检查 `template_bundle` 只 **warn**（退出码停在 1，不阻断）；按模板页说明换新版 `SLCN-MIX.sty`/`SLEN.sty` 后重新生成目录 | 无（保留向后兼容，不强制） |
| `sortname` 与内容身份（引用库） | B-377 起 `sortname` 是**纯排序层覆盖字段**，不计入 `content_sha256`：改它不再触发 rehash | 旧库里显式含 `sortname` 的记录摘要与新算法不一致（纯排序字段，不影响条目内容） | 一次性迁移 `Engine/tools/migrate_sortname_identity.py --db <库> --dry-run`（看 CSV/summary），确认后 `--apply` 重算 sha；真实笔记库只在 3.B377 关闭 App 后执行 | 一次性（当前真实库 0 条显式 `sortname`，`changed` 预期 0） |
| 本机未装 `caspervector.sty`（R08 口径修正） | `kpsewhich caspervector.sty` 为空；负对照 `\usepackage{caspervector}` 会报 `.sty not found` | **不影响**交付编译：模板用的是 biblatex 样式名 `style=caspervector`，由 `biblatex-caspervector`（v0.3.7 起提供 `.bbx`/`.cbx`）解析；骨架 `xelatex → biber → xelatex ×2` 实测 rc=0、PDF 正常出 | 装 `biblatex-caspervector`（TeX Live 用 `tlmgr install biblatex-caspervector`）即可；自检请用 `style=caspervector` 的真实骨架，别拿 `\usepackage{caspervector}` 当判据 | 无（口径修正） |
| 大期合并内存 | 整期合并 PDF 大文件时内存占用高（历史观察） | 极端期可能较慢 | 分批合并，或加大内存 | 待观察 |

## 反馈与更新

发现未列入的限制、或绕行办法不适用：请到 GitHub Issues 反馈（附版本号与复现步骤）。
本页随版本更新；历史版本的「已知问题」以对应 Release 正文为准。

## 失败诊断的边界

- Flet 单壳的失败信息分三层：**结果横幅**（可读原因 + 产物路径）、**日志区摘要层**（可切「只看摘要」）、
  **原始输出**（引擎末行契约与退出码）；复现问题用「设置 → 诊断包」导出或复制诊断信息（已脱敏，不含 API Key/正文）。
- **设置 → 环境检查**只调用 `Engine/envcheck.py --json`（只读，B-377 起九项）：引擎运行时 / TeX / biber
  （含 CLDR 中文排序 locale）/ LibreOffice / git / 磁盘 / 输出目录 / 模板 / Windows 字体；
  不改系统、不上传。
- 引擎退出码语义不变：`proofcheck` / `checkbib` 的 1 = **有命中项，不是失败**；`toc` 的 1 = 已完成但需人工核对。
- 缺 `xelatex`/`biber` 等属工具缺失，按提示补装后重跑；诊断信息只在本机生成。
