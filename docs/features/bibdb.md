# 引用库

> **本页目录**：[一句话定位](#一句话定位) · [入口](#入口) · [前提](#前提) · [操作步骤](#操作步骤) · [示例](#示例) · [限制与已知问题](#限制与已知问题)

## 一句话定位

「引用库」把编辑部已核实的文献沉淀成一份可复用的库：**先查库，再决定查证、入藏、治理**。往期成品 `reference.bib` 的条目视为已核实；AI 结果与粘贴文本默认未核实。查库只读；写入库的视图一律「先预演、再确认、再写一条本地提交」，绝不推送。

## 入口

左侧导航 **引用库**，名下按「查阅 / 采录 / 治理」三组排布，共十个视图，另有一个独立的「版本与同步」页：

| 组 | 视图 | 作用 |
|---|---|---|
| 查阅 | 概览 | 库文件路径、条目数、别名合计、库大小 |
| 查阅 | 查库 | 基本 / 高级两页签，按 10 个字段检索并复制 BibTeX |
| 采录 | 入藏 | 单篇 `.bib`、整期目录、粘贴 bib 文本三种来源 |
| 采录 | AI 辅助处理 Bib | 生成任务书、收回件、审阅采纳后并入 |
| 治理 | 待处理 | 冲突与 lint 两类待办的中心入口 |
| 治理 | 编辑 | 单条增改，含字段对照 |
| 治理 | 查重合并 | 重复记录只报告，逐组人工裁决 |
| 治理 | 字段归位 | 库值与 AI 值的字段差异逐项归位 |
| 治理 | 库健康 | 批量体检与批量裁决 |
| 治理 | 引用库设置 | 显示库位置、条目数与别名规模（只读） |

顶部[命令面板](./search)（`⌘K` / `Ctrl+K`）可搜索这些视图与常用命令，例如「新建单篇」「刷新引擎状态」。

## 前提

- **库文件**：库在设置中心 → 路径里指定，正文是 JSONL；缺库时大多数视图会提示先入藏或先建库，不会自行造一份空库。
- **写库保护**：治理类视图写库前会记下库指纹，再校验一次；中途库被别的窗口改过就停下来，不会拿旧判断覆盖新内容。
- **AI（可选）**：用 AI 辅助处理 Bib 前需在[设置中心 → AI 与模型](./settings)配好 API Key、接口地址与模型，并打开 AI 功能总开关；密钥只存本机设置，不进日志。预算超限即退出，不发请求。
- **Git（可选）**：写库会留一条本地提交（只含库文件），便于回退；不要求库挂在远程仓上，也不会自动推送。

## 操作步骤

### 查库（只读）

1. 进「查库」，在基本页签按 key / 别名 / DOI / 题名检索；高级页签可按 10 个字段组合条件，每个字段支持包含、前缀、精确、模糊四种匹配（年份、DOI、别名不收模糊）。
2. 年份可写单值、区间或比较式（`2003`、`1990-2000`、`>=2010`）。
3. 结果可排序（相关度 / 年份 / 作者），每页最多 1–200 条；模糊匹配有严格门槛（0.90），不会把相近题名都塞进来。
4. 每条都能看「为什么命中」，需要引用时「复制 BibTeX」拿到引擎值。查库零写库、零 Git。

### 入藏（把新条目收进库）

1. 选来源：单篇 `.bib`、整期目录（自动扫各篇的 `reference.bib`）、或直接粘贴 bib 文本。
2. 先看**预演**：新增、重复、冲突分别列出，此时库还没变。
3. 确认口径：粘贴与 AI 结果默认「未核实」；整期成品 bib 视为已人工核对。二次确认后才真正写库，并校验库指纹。
4. 提交后看结果摘要：入库条数、跳过条数与原因。

### AI 辅助处理 Bib

1. **准备任务**：选处理范围与条目范围，生成任务书（带 `TASK-ID`）。
2. **获取结果**：Chat 通道粘贴回件，或 API 通道直接跑；只处理库里已有条目，不凭空造条目。
3. **审阅采纳**：逐条看原值与 AI 值的字段差异，默认保留库值；阻断项（缺关键字段、无法判定）不能采纳。
4. **并入目标 Bib**：确认后才写库，并留一条本地提交；写入对象只有库文件与它的 JSONL 正文，不碰稿件。

### 治理（写库）

1. 「待处理」把冲突与 lint 汇到一处：同一作品多条记录、字段冲突、缺字段、`entry_type` 笔误等。
2. 进「编辑」改单条，「查重合并」逐组裁决重复记录（工具只报告，不自动合并），「字段归位」把字段差异按项归位（可「全选库值」或「全选 AI 值」批量处理），「库健康」做批量体检与批量裁决。
3. 每个视图都是三步：**预演**（记下库指纹，不改库）→ **二次确认** → **写入并校验指纹**。写成功只产生一条本地提交。
4. 要回退时用「版本与同步」：提交、推送、回退都逐次确认；推送只推库文件、不加 force；回退是生成一条新提交，不做硬重置。

### 分页与库变化

库按每页 100 条分页，翻页接口返回 `offset / limit / count / total_matched / has_more / next_offset` 六个字段和库指纹 `db_sha256`。翻页途中库被改动时，不会把新旧两页拼在一起——会提示刷新后重查。查询条件一改就重置回第一页；选中身份用 key，复制 BibTeX 用引擎值。

## 示例

一篇来稿的 `reference.bib` 里有 37 条，其中 21 条库里已有：

| 阶段 | 输入 | 产出 |
|---|---|---|
| 入藏预演 | 单篇 `.bib` | 新增 10、重复 21、冲突 6 的预演清单（库未变） |
| 二次确认 | 预演清单 | 库新增 10 条，留一条本地提交 |
| 查库 | 题名关键词 | 六列表格（题名 / 作者 / 年份 / key / 状态 / 来源） |
| AI 辅助处理 Bib | 库内待核实条目 | 任务书 → 回件 → 字段差异 → 采纳后并入 |
| 字段归位 | 字段差异清单 | 按项归位（可全选库值 / 全选 AI 值） |

入库口径一句话：**往期成品 bib 已核实；AI 结果与粘贴文本默认未核实；重复记录只报告不自动合并。**

## 限制与已知问题

- **写库必须两次确认**：预演不改库，确认才写；库指纹对不上就停。别在多窗口里同时改同一份库。
- **重复记录不会自动合并**：工具只做判定与对照，合并与否由人裁决；批量按钮是「全选某个值」，不是「一键合并」。
- **AI 只处理库内条目**：没有的条目不会被凭空创建；AI 初排的文献核实范围有上限（默认 120 条），查库命中会跳过检索与 AI。
- **长列表与窄窗**：库大时列表滚动较慢属正常；窄窗口下字段值会换行显示，长路径会提示实际位置。
- **清理预览与撤销**：入藏与治理产生的临时文件在预览里列出，确认后才清理；撤销只还原本批次，不覆盖同名文件。
- **命令行不是必须**：所有常用操作都能在界面完成；命令行只是高级用法。

失败时先看结果摘要与日志末行；需要环境结论去[设置中心 → 引擎与环境](./settings)，把信息发给编辑部用「复制诊断信息（文本）」或「导出为文本文件」。
