# 单篇稿件

侧边栏「单篇稿件」提供 **初排转换 → 一校核查** 两个子页。
需要单独核实、审阅并写回一份 Bib 时，进入[「引用库 → AI 辅助处理 Bib」](./bibdb)。
合并整期 PDF 的「合并文件」步骤在[「整期装配」](./assembly)页的六步流水线里；
引用库详情见[「引用库」](./bibdb)。

## 初排转换

把作者源文件（`.docx` / `.tex`）转成符合本刊排版规范的 **可编译 `.tex`**。

::: warning 先整理源文件夹
初排会把源稿件所在的**整个文件夹**（含子文件夹里的全部文件）归档进产物的 `original/`。
运行前请把来稿放进一个专用的干净文件夹，只放本次要用的源文件和配套素材（图片、`.sty`、`.bib` 等）；
旧稿、临时文件、无关资料会被一并归档，请勿混放。
:::

1. 选择「源稿件」与「输出根目录」，这是必填的两项。
2. 在「输出选项」选择是否编译 PDF、清理临时文件；需要时展开「更多输出选项」。
3. 要补刊期、稿件信息、附件或元数据时，展开「稿件信息、附件与元数据（可选）」；留空沿用自动解析或模板默认值。
4. 普通初排点「开始转换」；需要先取得 AI 建议再逐项核对时，点「使用 AI 辅助初排」。
5. 完成后查看实际产物与编译结果，再进入一校核查。

- **浏览即用**：Flet 单壳（v1.5.0 起）统一用输入框旁的「浏览…」打开**系统原生对话框**选择源文件与
  输出根目录，也可以把路径直接粘贴进输入框。**不接收系统拖放**（Flutter/Flet 桌面端未暴露外部
  拖放 API，见[已知限制](../reference/known-limitations)），拖到窗口上不会有反应。
- **高级参数（可选）**：展开「稿件信息、附件与元数据（可选）」后，可填写卷、期、年份、页码、收稿日期、作者、篇名、
  参考文献 `.bib`、语种、责编、基金、附加参考文献、样式文件、模板骨架；留空就用模板默认，
  **填了才传给引擎**。输出名 / 作者名 / 文献库路径同理（留空自动推断）。
- **人工元数据表单**：在可选稿件信息区的「元数据（可选）」中填中英文题名/摘要/关键词、1–5 位作者
  与多单位（每位作者每语言最多 3 行）；留空 = 不覆盖（沿用引擎自动解析）。表单值随运行写成
  临时 JSON（`--metadata-json`，跑完即删），正文信息覆盖与 `.tex` 元数据文件都让位给它。
  点「预览元数据」用**同一条 argv** 加 `--metadata-preview-out` 只读预览（字段 / 生效值 / 来源 / 状态，
  冲突与未识别单独列出）：只写预览 JSON，不建产物目录、不写产物与交接单。英文关键词两个模板都
  没有槽位，引擎日志会提示人工放置（填了不会丢）。
- **元数据文件（高级兜底）**：LaTeX 纯正文稿可指上一轮模板稿 `.tex`；`.docx` 不提供自动识别
  （引擎的 `.docx` 提取能力仅 CLI 高级可用：提取题名/作者/单位/邮箱/摘要/关键词并合成临时 `.tex`，
  只填第一作者槽位；0 字段 / 坏 docx / 未知二进制 → 退出 2）。老式 `.doc` 不支持，请先另存为 `.docx` 或 `.tex`。
  **两段式 AI 协同**：人工元数据表单可用于第一段（值写进初排，第二段沿用初排元数据、再改表单不生效）；
  仍不支持 Word 元数据文件（请用 `.tex` 元数据文件）。
- **出版信息**：卷、期、年、起止页、收稿日期一次填好，产物页眉 / 页脚才正确。
- **参考文献与产物**：产物为 `<作者>.tex`、`reference.bib`、模板 `.sty`；《文献核实任务书》
  （`<名>_文献核实.md`）普通初排默认不生成，需要时走两段式第一段或 CLI `--verify-refs`（高级）。
  **来稿附 `.bib` 的优先采用；未附时，Word 文末参考文献清单或手写 `\bibitem` 会被自动解析 / 转换成
  `reference.bib`——条目类型与字段可能需人工核对（手写 `\bibitem` 稿尤其要看一眼）。**
- **引用库只读比对**：普通初排日志多一行「引用库比对：命中 X / 候选 Y / 未命中 Z（只读，不改产物）」
  （无引用库时静默；`--no-bibdb-verify` 可关）。命中只用于跳过检索 / AI 与任务书提示，**不自动改稿**。
- **AI 辅助**：可选择 Chat 或 API 获取建议，随后核对采纳范围和拟应用结果，确认后才交付。
  API 配置在「设置 → AI」；请求可能产生费用，失败后由你手动重试。密钥只存本机设置，
  通过环境变量传给引擎，不进入任务书、日志或命令行参数。

### AI 辅助初排

在「单篇稿件 → 初排转换」选好源稿和输出根目录，点「使用 AI 辅助初排」。转换输入与选项会收纳为摘要，需要修改时可重新展开；「返回普通转换」可切回普通初排。

1. **准备任务**。选择 Chat 或 API，以及文献核实、初排检查、文字纠错等执行范围，再点「生成任务书」。文献核实按可识别引用及必要依赖委派，原 Bib 的条目仍保留。
2. **获取结果**。Chat 通道先复制任务书给对话工具，再粘贴带同一 `TASK-ID` 的完整回复，点「读取并检查结果」；也可展开「从文件读取结果（替代粘贴）」选择回复文件。API 通道点「开始 API 核实」；失败时修正配置或手动重试。
3. **审阅采纳**。选择采纳范围，逐项审阅原稿与 AI 回件的实质字段差异，默认保留原稿。库内无匹配或该字段无可用库值时，只能选择原稿或 AI 回件；有可用库值时才可选择库值。点「生成拟应用结果」检查候选；改过字段取值或采纳范围后，旧候选失效，须重新生成才能对比或交付。
4. **完成**。核对候选后点「完成初排转换」。完成页显示真实采纳结果与编译状态，主操作是「打开交付目录」。「本次采用详情（只读）」保留处理记录；完整路径和任务编号在「任务详情」中查看、复制。

**文献范围**：显式 `\nocite{键名}` 及 `crossref`、`xdata` 等必要依赖可以纳入核实；`\nocite{*}` 不扩大委派范围，未识别到可核引用时生成零条文献核查任务。普通未引用条目的原文不进入任务书，但仍保留在最终 Bib。

**对比与交付**：「在 VS Code 里对比…」左侧是本次任务冻结的旧 Bib 副本，右侧是当前候选 Bib 副本。修改副本不会改变交付；引擎按当前任务、回件、预览与候选文件身份执行实际写入。编辑器不可用时，可复制两份副本路径自行查看。

当前阶段的操作区固定在审阅内容之外，长列表可单独滚动。完成后不再编辑这次采纳；需要撤销时展开「其他操作」，核对恢复范围并确认。决定保留原初排结果时，可在交付前选择「其他操作 → 按原稿交付…」。

::: info 旧版模板稿
作者用旧版模板（或把自定义命令放在本地 `.sty`）提交时，工具会按「正文用到且现行模板缺」自动迁移定义；
本地非标准命名的旧模板 `.sty` 不会被错误加载，编译器会给出明确提示。
:::

## 引用库中的 AI 辅助处理 Bib

「引用库 → AI 辅助处理 Bib」用于单独核实、审阅并写回一份目标 Bib。它与初排中的 AI 辅助采用相同的「准备任务 → 获取结果 → 审阅采纳 → 完成」交互，执行范围限定为文献核实（`bib_verify`）：只输入 `.bib`，不关联正文，也不提供初排检查或文字纠错。初排页仍保留完整的执行与采纳范围；其交付是一组稿件文件，此处更新选定 Bib。

1. 选择要处理的目标 `.bib`。
2. 选择 Chat 或 API；执行范围固定为文献核实，生成任务书并取得结果。
3. 逐项审阅实质字段差异，默认保留原稿；库内无匹配或该字段无可用库值时，只能选择原稿或 AI 回件。生成拟应用结果后可用 VS Code 对比；改选须重新生成。
4. 确认后点「并入目标 Bib」。完成页显示实际写入情况，点「打开结果位置」查看文件。

- **不改中央库**、不自动入藏，也不自动提交到 Git。写入前引擎备份目标，符合恢复条件时可在「其他操作」中撤销。
- **处理范围**：所选 Bib 的全部有效条目构成文献核实范围；库内安全命中沿用已核实记录，其余条目进入 AI 任务。仅提供文献核实类别，采纳可取消；取消后任务保留、可继续审阅，零写入不显示为已应用。正文相关检查及文字纠错请在初排页中执行。
- **旧任务**：包含正文路径或额外执行类别的旧库页任务会保留原数据，但不会在此页续跑；请重新生成文献核实任务。
- 真实阻断项（必保键缺失、键重复、条目残缺、Bib 块未闭合、`@string` 定义冲突、依赖成环）会逐条显示，处理前不能应用。字段取值不同不等于阻断。
- VS Code 对比展示冻结旧 Bib 和当前候选 Bib 的副本，实际写回仍按引擎核对的当前任务、回件、预览与候选文件身份执行。编辑器不可用时，可复制两份副本路径自行查看。

需要只读回读报告或命令行并回时，见引擎用法中的 `checkbib.py`；它与此处经过预览确认的 AI 写回流程分别使用。

## 一校核查

按手册的一校规范逐条核查初排后的 `.tex`（29 条规则）。默认只出报告，写到稿件同目录的
`<名>_一校核查.md`（**不覆盖稿件**）；勾「顺手把无歧义的改掉（另存新文件）」才另写
`<名>_一校核查后.tex`，输入文件不动。语种可选「自动 / 中文 / 英文」，默认由引擎按正文判断。

完成后在结果卡里显示四项计数（需人工 / 可自动改 / 命中合计 / 规则数）、命中规则前 5 条，
并可「打开报告」看全文。报告只列需要人工判断的「命中项」（每条给出依据与修改建议），
可自动改项初排已默认处理，报告摘要里只计数；带 `--fix` 时另附「已自动改的部分」表
（规则/行/原文/改成）。没有命中项即通过；**有命中项属于需要处理，
不是程序失败**（退出码 1 是「有命中」；退出码 2 才是失败，失败文案会带退出码）。

## 输出约定

| 产物 | 说明 |
|---|---|
| `<作者>.tex` | 套用本刊模板的初排正文 |
| `reference.bib` | 整理后的参考文献库；保留未委派核实的原条目与依赖 |
| `<作者>.pdf` | 勾选编译 PDF 且编译成功时生成 |
| `<模板>.sty` | 本刊模板样式（随包提供） |
| `original/` | 源文件夹整目录归档（含全部文件与子文件夹；不删源文件，运行前请把源文件放进干净的专用文件夹） |
| 文献核实任务书 | AI 准备任务后生成，完整路径在「任务详情」中查看；普通初排默认不生成 |
| 工作区内的候选 Bib / TeX | 「生成拟应用结果」产生，确认交付前不写最终目录 |
| `compare/<对比编号>/` | VS Code 对比副本，文件名为 `reference.bib` / `reference_proposed.bib` |
| `AI交付检查说明.md` | AI 初排交付后生成，记录实际采纳、待人工项与编译状态 |
| `*.log` | 编译日志（保留，便于排查） |

命令行的独立文献核实任务书、分卷及分片参数，见仓库中的 `Engine/docs/GUIDE.md`。

## 身份与保护边界（AI 辅助初排）

- **任务身份**：任务书带 `TASK-ID`，回复须属于同一任务。另一任务的回复会被拒收，不能靠相同引用键混入。
- **冻结输入**：生成任务书时冻结本次输入和初排设置；源稿或附件变化后，应重新准备任务，不能继续交付旧候选。
- **候选身份**：实际交付前，引擎核对当前任务、回件、预览编号及候选文件指纹。改选后须重新生成；候选被外部修改时拒绝交付，编辑 VS Code 对比副本也不会改变候选。
- **交付与撤销**：生成任务书或拟应用结果不等于完成交付。完成页以实际引擎回执为准；交付后须先撤销才能再次交付，撤销时发现外部改动会停止恢复。
- **人工核对**：实际写入、引文闭合和编译成功分别确认。未勾选编译时不代表已有可用 PDF；题名、作者、版式、页数、公式、图表、引用及脚注仍须人工核对。

## 失败时看什么

Flet 单壳（v1.5.0 起）把「运行日志」做成**底部浮层**（VSCode 输出面板式：始终在页面最上层、
可收起/展开，开始运行时自动展开），日志区上方给**结果横幅**：完成显示产物目录（可「打开产物」/
「复制路径」），失败显示引擎末行契约（一句原因 + 退出码），原始输出始终留在日志区（摘要 / 原始可切换）。
初排转换退出码 2 是失败；一校核查（`proofcheck.py`）退出码 1 是「有命中，不是失败」；
离线回读校验可用命令行 `checkbib.py`；「引用库 → AI 辅助处理 Bib」按任务状态展示核实、候选与实际写入结果。
旧外壳的**诊断卡 / 诊断包**在 Flet 单壳里改为「设置 → 诊断包」：可导出或复制诊断信息（已脱敏，导出需二次确认）；
需要环境结论时去「设置 → 环境检查」，日志区另有「复制 / 清空」与「只看摘要」开关。
