# 单篇稿件

> **本页目录**：[一句话定位](#一句话定位) · [入口](#入口) · [前提](#前提) · [操作步骤](#操作步骤) · [示例](#示例) · [限制与已知问题](#限制与已知问题)

## 一句话定位

「单篇稿件」处理**一篇**来稿：**初排转换**（Word / LaTeX → 套用本刊模板的可编译 `.tex`，可顺带编译 PDF）与 **一校核查**（按 29 条规则逐条核对初排稿）。需要单独核实、审阅并写回一份 Bib 时，去[「引用库 → AI 辅助处理 Bib」](./bibdb)。

## 入口

左侧导航 **工作区 → 单篇稿件**，名下两个子视图：

| 子视图 | 用途 |
|---|---|
| **初排转换** | 来稿转初排稿；普通转换与「使用 AI 辅助初排」共用同一页 |
| **一校核查** | 按一校规范核对初排后的 `.tex`，默认只出报告 |

两处补充入口：初排页的「更多输出选项」内的编译修复相关按钮（见下文），以及顶部[命令面板](../features/search)（`⌘K` / `Ctrl+K`）里直接搜索「新建单篇」「运行当前页」等命令。

## 前提

- **TeX**：要出 PDF 就需本机装 XeLaTeX + biber（TeX Live / MiKTeX / MacTeX）。只做转换不编译则不需要。
- **LibreOffice（条件必需）**：含 MathType / OLE 公式的 Word 稿需要它导出公式图；缺失时转换仍完成，公式位置留「公式图缺失」占位。
- **AI（可选）**：用 AI 辅助初排或 AI 辅助编译修复前，需在[设置中心 → AI 与模型](./settings)填好 API Key、接口地址与模型，并打开「AI 功能总开关」。密钥只存本机设置，不进日志。
- **干净的源文件夹**：初排会把源稿所在的**整个文件夹**（含子文件夹）归档进产物的 `original/`。请把来稿放进专用干净文件夹，只放本次要用的源文件与配套素材（图片、`.sty`、`.bib` 等），不要混放旧稿与临时文件。

## 操作步骤

### 初排转换

1. 选择**源稿件**与**输出根目录**（两项必填）。点「浏览…」用系统原生对话框选择，也可以把路径粘贴进输入框；应用**不接收系统拖放**（见[已知限制](../reference/known-limitations)）。
2. 在「输出选项」决定是否**编译 PDF**、**清理临时文件**；其余行为收在「更多输出选项」里（导出原稿 PDF、强制覆盖等）。
3. 需要补刊期、稿件信息、附件或元数据时，展开「稿件信息、附件与元数据（可选）」；留空沿用自动解析或模板默认值。
4. 普通初排点**「开始转换」**；想先取得 AI 建议再逐项核对，点**「使用 AI 辅助初排」**。
5. 完成后看结果横幅给出的产物目录，再进入一校核查。

### 使用 AI 辅助初排

1. **准备任务**：选择 Chat 或 API，以及文献核实、初排检查、文字纠错等执行范围，点「生成任务书」。
2. **获取结果**：Chat 通道把任务书交给对话工具，再粘贴带同一 `TASK-ID` 的完整回复（也可从文件读取）；API 通道点「开始 API 核实」。
3. **审阅采纳**：逐项核对原稿与 AI 回件的实质字段差异，默认保留原稿；库内无匹配或该字段无可用库值时，只能选原稿或 AI 回件。确认后生成拟应用结果；改过取值或范围，旧候选即失效。
4. **完成**：核对候选后点「完成初排转换」。完成页显示真实采纳结果与编译状态，主操作是「打开交付目录」。

> **执行范围与采纳范围是两个独立分组**：执行范围决定这次发给 AI 什么，采纳范围决定拿回来的结果用哪几类。只管执行不管采纳，等于「让 AI 看但不改」。

### AI 辅助编译修复

初排编译失败后，工具会**先用本机规则尝试自动修正常见的宏冲突**（本地能修的会标「本地已修」）；本机修不好、需要外发时，在**AI 辅助初排**里逐篇确认，界面只显示只读披露（目标主机、本次预算）与一个发送按钮。点「**确认并发送一次**（真实付费外发）」即本次授权：**一次确认只对应一次发送**，不会自动重试、不会重复发送或串稿，未经确认不会联网。回件走「导入编译修复回件 → 审阅编译修复差异」，采纳前仍可逐项核对；本机记录保留 30 天，可在「编译修复本机留存」里清理。

### 一校核查

1. 选择初排后的 `.tex`，语种可选「自动 / 中文 / 英文」（默认由引擎按正文判断）。
2. 默认**只出报告**，写到稿件同目录的 `<名>_一校核查.md`，不覆盖稿件。
3. 勾「顺手把无歧义的改掉（另存新文件）」才另写 `<名>_一校核查后.tex`，输入文件不动。
4. 结果卡显示四项计数（需人工 / 可自动改 / 命中合计 / 规则数）与命中规则前 5 条，可「打开报告」看全文。

## 示例

一篇 Word 来稿 `Lei_Li.docx`，输出根目录选期目录根，勾选编译 PDF：

| 产物 | 说明 |
|---|---|
| `Lei_Li.tex` | 套用本刊模板的初排正文 |
| `Lei_Li.pdf` | 勾选编译且编译成功时生成 |
| `reference.bib` | 整理后的参考文献库（保留未委派核实的原条目与依赖） |
| `SLCN-MIX.sty` | 本刊模板样式（随包提供） |
| `original/` | 源文件夹整目录归档（含全部文件与子文件夹，不删源文件） |
| `Lei_Li_一校核查.md` | 一校核查报告（只列需要人工判断的命中） |
| `Lei_Li_一校核查后.tex` | 勾选「顺手改掉」时另存的新文件 |
| `参考文献核对.txt` | 引用与 bib 的对照清单 |
| `compare/<对比编号>/` | VS Code 对比副本（`reference.bib` / `reference_proposed.bib`） |
| `AI交付检查说明.md` | AI 初排交付后记录实际采纳、待人工项与编译状态 |
| `*.log` | 编译日志，保留便于排查 |

## 限制与已知问题

- **29 条规则**：一校核查当前覆盖 29 条规则；报告只列需要人工判断的命中，可自动改项初排已默认处理，报告里只计数。规则清单见维护者文档。
- **有命中不是失败**：一校核查退出码 1 表示「有命中项，需要处理」，不是程序失败；退出码 2 才是失败。
- **不接收系统拖放**：Flet 桌面端未暴露外部拖放 API，拖到窗口上不会有反应，统一走「浏览…」或粘贴路径。
- **AI 只是建议**：采纳的文字纠错只写交付候选，源稿不变；实际写入、引文闭合与编译成功要分别确认。未勾选编译时不代表已有可用 PDF，题名、作者、版式、页数、公式、图表、引用与脚注仍须人工核对。
- **何时不该用 AI 自动修复**：作者原意、术语、公式、引用键、命令与路径都不该交给自动修复；跨度大得像改写、两端都像专名、落在保护区的改动一律只报告不改。机械校验只能证明位置与范围，不能证明语义没变——改过的句子仍须人工复核。作者来稿始终只读，任何修复都只写产物。
- **旧模板稿**：作者用旧版模板（或把自定义命令放在本地 `.sty`）时，工具会按「正文用到且现行模板缺」自动迁移定义；本地非标准命名的旧模板 `.sty` 不会被错误加载，编译器会给出明确提示。
- **Word 元数据**：`.doc` 不支持自动识别，请先另存为 `.docx` 或 `.tex`；`.docx` 的元数据自动提取仅命令行高级可用，界面请用「元数据（可选）」表单。

失败时先看底部浮层日志的结果横幅（一句原因 + 退出码）与原始输出；需要环境结论去[设置中心 → 引擎与环境](./settings)，需要把信息发给编辑部时用「复制诊断信息（文本）」或「导出为文本文件」（已脱敏，导出前可先核对预览）。
