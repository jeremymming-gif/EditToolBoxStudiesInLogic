# 单篇稿件

侧边栏「单篇稿件」是编辑流程的前两步（Flet 单壳 v1.5.0 起）：**初排转换 → 一校核查**，
在左侧导航「单篇稿件」下切换，一次只做一件事；参考文献规范化已移到[「引用库 → 规范化」](./bibdb)。
合并整期 PDF 的「合并文件」步骤在[「整期装配」](./assembly)页的六步流水线里；
引用库详情见[「引用库」](./bibdb)。

## 初排转换

把作者源文件（`.docx` / `.tex`）转成符合本刊排版规范的 **可编译 `.tex`**。

- **浏览即用**：Flet 单壳（v1.5.0 起）统一用输入框旁的「浏览…」打开**系统原生对话框**选择源文件与
  输出根目录，也可以把路径直接粘贴进输入框。**不接收系统拖放**（Flutter/Flet 桌面端未暴露外部
  拖放 API，见[已知限制](../reference/known-limitations)），拖到窗口上不会有反应。
- **高级参数（可选，常显）**：「高级参数」区直接列出卷、期、年份、页码、收稿日期、作者、篇名、
  参考文献 `.bib`、语种、责编、基金、附加参考文献、样式文件、模板骨架；留空就用模板默认，
  **填了才传给引擎**。输出名 / 作者名 / 文献库路径同理（留空自动推断）。
- **人工元数据表单（默认收起）**：点开「元数据（可选）」折叠区填中英文题名/摘要/关键词、1–5 位作者
  与多单位（每位作者每语言最多 3 行）；留空 = 不覆盖（沿用引擎自动解析）。表单值随运行写成
  临时 JSON（`--metadata-json`，跑完即删），正文信息覆盖与 `.tex` 元数据文件都让位给它。
  点「预览元数据」用**同一条 argv** 加 `--metadata-preview-out` 只读预览（字段 / 生效值 / 来源 / 状态，
  冲突与未识别单独列出）：只写预览 JSON，不建产物目录、不写产物与交接单。英文关键词两个模板都
  没有槽位，引擎日志会提示人工放置（填了不会丢）。
- **元数据文件（高级兜底）**：LaTeX 纯正文稿可指上一轮模板稿 `.tex`；`.docx` 不提供自动识别
  （引擎的 `.docx` 提取能力仅 CLI 高级可用：提取题名/作者/单位/邮箱/摘要/关键词并合成临时 `.tex`，
  只填第一作者槽位；0 字段 / 坏 docx / 未知二进制 → 退出 2）。老式 `.doc` 不支持，请先另存为 `.docx` 或 `.tex`。
  **两段式 AI 协同**：人工元数据表单可用于第一段（值写进初排，第二段沿用初排元数据、再改表单不生效）；
  仍不支持 Word 元数据文件（请用 `.tex` 元数据文件）。
- **出版信息**：卷、期、年、起止页、收稿日期一次填好，产物页眉 / 页脚才正确。
- **参考文献与产物**：产物为 `<作者>.tex`、`reference.bib`、模板 `.sty`；《文献核实任务书》
  （`<名>_文献核实.md`）普通初排默认不生成，需要时走两段式第一段或 CLI `--verify-refs`（高级）。
  **来稿附 `.bib` 的优先采用；未附时，Word 文末参考文献清单或手写 `\bibitem` 会被自动解析 / 转换成
  `reference.bib`——条目类型与字段可能需人工核对（手写 `\bibitem` 稿尤其要看一眼）。**
- **引用库只读比对**：普通初排日志多一行「引用库比对：命中 X / 候选 Y / 未命中 Z（只读，不改产物）」
  （无引用库时静默；`--no-bibdb-verify` 可关）。命中只用于跳过检索 / AI 与任务书提示，**不自动改稿**。
- **AI 协同初排（两段式，默认关）**：单篇稿件页 AI 区勾「AI 协同初排（两段式）」→ 第一段只写
  **暂存目录** `<输出目录>/<名_姓>_待核/` + 文献核实任务书（含「附一、初排低置信项」与
  「附二、回填说明」；状态「待人工核实（未交付）」），**不交付、不调用 API、零上传**；暂存目录、
  任务书路径与状态显示在 AI 区。把任务书交给任意外部 chat 模型，回填完整 BibTeX 代码块 + 附一 JSON
  （可拆成多个文件）→ 回界面「添加回填文件」逐个加入（暂存目录留空会按输出根目录与源稿自动发现，
  也可手填或点「自动发现暂存目录」）、按需勾「第二段直接改产物（`--coop-apply`；默认不勾 = 只记录
  建议）→ 点「运行」跑第二段。成功后摘要显示「文献回填 x/y、低置信回复 n（已应用 a / 仅记录 b，
  待人工 c）」，数字取自暂存目录的 `_AI协同状态.json`。第二段可重跑（幂等早退）；`--coop-apply`
  决定须在点运行前做。软限制：建议清单第二段跑完才生成；「按片拆分任务书」与元数据表单不在
  Flet 面板里；**软件零上传、零 API、零费用**。
- **可选：正文放进任务书（两段式，默认关）**：AI 区再勾「把正文放进任务书（`--coop-fulltext`）」并选
  范围「引用上下文（默认）/ 全文」；勾上后第一段任务书在「附二」后多「附三、正文全文 / 引用上下文」，
  整篇写入（保留体积估算 / 超长提示；外部 chat 吃不下时自行分段或改用「引用上下文」）。勾选后任务书
  还会多一节「附四、初排分析」（引用覆盖 / 脚注转换 / 字段补全 / 占位符 / CJK 译名 / 低置信复核），
  **默认只报告、不写产物**——第二段把解析结果落 `<名>_AI全文分析.md/.jsonl` 并计入协同记录，不接
  「直接改产物」。只写进**本机任务书**；**软件零上传、零费用**；仅第一段生效。
- **AI 核实（直连 API，会产生费用，默认关）**：AI 区勾「AI 核实（直连 API）」后，引擎把**文献元数据**
  发到设置页配置的端点补全缺项，运行前界面给出**上传预览**（只列文献元数据与任务书摘要，**正文、脚注、
  整篇稿件不发送**）。参数在「设置 → AI」：接口地址（默认 `https://api.deepseek.com/v1`）、模型
  （默认 `deepseek-flash`）、协议 chat / responses、思考开关、单篇预算 / 单批预算（tokens，默认
  30000 / 1000000，0 = 不限）；AI 核实区勾「不自动并回产物（`--no-ai-merge`）」则只出报告（AI 产物开关，与 bib 并回无关）。
  **预算硬停**：引擎在发出任何请求**之前**退出（退出码 2），界面显示「预算不足，未发起请求」，
  不会绕过闸门偷偷请求。Key 只存本机设置文件、只经环境变量传给引擎，**不进日志、不进 argv**。
- **AI 全文直连核查不在 Flet 范围**：`--llm-fulltext`（把正文分片发给模型、生成
  `<名>_AI全文复核.md` 并自动应用 BIB/META/FN 建议）仍只在旧 Tk/SwiftUI 外壳与 CLI 里；
  Flet 面板不提供该入口，需要时用 CLI（参数见 `Engine/docs/ENGINE_API.md`），且同样受预算闸约束。
- **AI token 预算**（「设置」页 AI 段）：单篇预算 / 单批预算默认 30000 / 1000000，0 = 不限，留空 = 不传；
  只约束直连 API 通道，外部 chat 两段式零费用不生效。
- **编译**：产物可直接编译出 PDF；编译失败会保留 `.log` 与中间文件便于排查。

::: info 旧版模板稿
作者用旧版模板（或把自定义命令放在本地 `.sty`）提交时，工具会按「正文用到且现行模板缺」自动迁移定义；
本地非标准命名的旧模板 `.sty` 不会被错误加载，编译器会给出明确提示。
:::

## 参考文献规范化（已移到「引用库 → 规范化」）

「参考文献规范化」（旧称「文献回读校验」，`checkbib.py`）不再作为本页的步骤：入口在
[「引用库」](./bibdb)页的**规范化**视图（采录组）；页内保留一颗「去引用库 → 规范化」按钮，
点一下直接跳过去。这一迁移不改变语义——它仍是**离线**维护动作（单篇生产流程不需要本步：
初排后的文献核对由两段式 AI 协同的第二段自动完成），**仍不生成任务书**（需要任务书走两段式第一段
或 CLI `--verify-refs`），**仍只出报告、不并回、不写库**（并回仅 CLI 可用，GUI 入口已移除，防覆盖正文；
CLI 并回前自动备份 `.ai前`）。交回来源二选一：选「交回的 `.bib` 文件」，或切到「粘贴文本」
把交回内容直接贴进来（走标准输入、不落中间文件；先点「识别粘贴的键」用 `--list-keys` 显示识别到几条、
键是什么，不写任何文件）。

- 校验回读的 bib 与正文引用是否一致、格式是否符合本刊规范；原件 `.bib`（可选）做逐字段对比，
  正文 `.tex`（可选）只读比对引用键闭合（`--tex` 不写回任何文件）。
- 输出「回读校验报告」：留空 = 自动落在交回 `.bib` 同目录的 `<基名>_回读校验报告.md`（粘贴模式且没填
  原件时落到系统临时目录）；也可填一个已存在目录或 `.md` 文件路径。
- 校验通过后，可到 **引用库 → 入藏** 把这份已核实 bib 存进编辑部引用库。

## 一校核查

按手册的一校规范逐条核查初排后的 `.tex`（29 条规则）。默认只出报告，写到稿件同目录的
`<名>_一校核查.md`（**不覆盖稿件**）；勾「顺手把无歧义的改掉（另存新文件）」才另写
`<名>_一校核查后.tex`，输入文件不动。语种可选「自动 / 中文 / 英文」，默认由引擎按正文判断。

完成后在结果卡里显示四项计数（需人工 / 可自动改 / 命中合计 / 规则数）、命中规则前 5 条，
并可「打开报告」看全文。报告只列需要人工判断的「命中项」（每条给出依据与修改建议），
可自动改项初排已默认处理，报告摘要里只计数；带 `--fix` 时另附「已自动改的部分」表
（规则/行/原文/改成）。没有命中项即通过；**有命中项属于需要处理，
不是程序失败**（退出码 1 是「有命中」；退出码 2 才是失败，失败文案会带退出码）。

## 输出约定

| 产物 | 说明 |
|---|---|
| `<作者>.tex` | 初排正文，可直接 xelatex 编译 |
| `reference.bib` | 规范化后的参考文献库 |
| `<名>_文献核实.md` | 参考文献核实任务书（两段式第一段 / CLI `--verify-refs` 才生成；普通初排默认不生成） |
| `<名>_AI全文复核.md` | 全文复核报告（`--llm-fulltext` 直连核查才有；Flet 面板不提供该入口） |
| `reference.bib.ai前` / `<名>.tex.ai前` | 自动应用前的回滚副本（本次运行被改过才有；重跑会覆盖） |
| `<模板>.sty` | 本刊模板样式（随包提供） |
| `original/` | 原稿归档（不删源文件） |
| `_AI协同记录.md` | 两段式协同记录（回填 / 并入 / 拒绝 / 待人工计数；只有走过第二段交付才有） |
| `<名>_AI建议.md` / `.jsonl` | 低置信建议清单（**第二段跑完才生成**；`--coop-apply` 未勾时只列清单） |
| `*.log` | 编译日志（保留，便于排查） |

## 失败时看什么

Flet 单壳（v1.5.0 起）把「运行日志」做成**底部浮层**（VSCode 输出面板式：始终在页面最上层、
可收起/展开，开始运行时自动展开），日志区上方给**结果横幅**：完成显示产物目录（可「打开产物」/
「复制路径」），失败显示引擎末行契约（一句原因 + 退出码），原始输出始终留在日志区（摘要 / 原始可切换）。
初排转换退出码 2 是失败；一校核查（`proofcheck.py`）退出码 1 是「有命中，不是失败」；
`checkbib.py` 已移到「引用库 → 规范化」，退出码语义见 [引用库 → 规范化](./bibdb)。
旧外壳的**诊断卡 / 诊断包**在 Flet 单壳里改为「设置 → 诊断包」：可导出或复制诊断信息（已脱敏，导出需二次确认）；
需要环境结论时去「设置 → 环境检查」，日志区另有「复制 / 清空」与「只看摘要」开关。
