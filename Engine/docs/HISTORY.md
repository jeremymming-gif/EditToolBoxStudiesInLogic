## 与原版（chenphilo 的 Editorialbox）的差异

「原版」指 Windows 上那个 `工具箱.exe`（上游是 chenphilo 的 `Editorialbox`）。
我们的 Windows 版界面**沿用了它的布局与交互**（MIT，署名见 `THIRD_PARTY.md`），
但功能实现换成了本项目的引擎 —— 所以下面这些差异对**两个平台**都成立。

以下都是经过**实际测试比对**确认的，不是猜测。

### 1. 「生成目录」作者名带垃圾文字 —— ✅ 已修复

原版取第二/三作者时用的是 **tex 里那一整行**（含行尾的中文注释），
导致生成的目录里粘上一串提示文字。**本版已修好。**

修复前 → 修复后（真实数据）：

| | 中文目录 | 英文目录 |
|---|---|---|
| 修复前 | `韩梅梅，王小明若需要请输入第二作者姓名并取消该行注释` | `\textit{{Meimei Han}, }` |
| 修复后 | `韩梅梅，王小明` | `\textit{Meimei Han, Xiaoming Wang}` |

**这一处修复同时解决了三个问题**，其中第 2 个是真正的数据丢失：

1. **中文目录的垃圾文字** —— 不再粘上「若需要请输入第二作者姓名…」
2. **英文目录丢失第二/三作者** —— 修复前只剩 `{Meimei Han}, `，逗号后面是空的。
   根因是那串残留注释本身是中文，程序据此判定「这是中文作者」，
   于是把*英文*作者名写进了*中文*字段，英文目录里就什么都没有了。
3. **英文目录多余的花括号** —— `\textit{{Meimei Han}}` → `\textit{Meimei Han}`

做法：从 tex 行里先去掉 LaTeX 注释（第一个未转义的 `%` 之后的内容），
再取最后一个 `{...}` 花括号组的值 —— 也就是**只保留真正的姓名**。

**对「检查tex信息」报告的影响**：报告中的**作者行**会随之变干净，
其余所有字段（卷号、期号、年份、起止页码、页数、字号、行距、标题、实际页数）
**与原版仍然完全一致**（已实际测试：56 处差异全部是作者行，非作者内容 0 差异）。

顺带修正了一处细节：两字姓名现在能正确插入 `\hspace{1em}`
（修复前因为名字后面粘着垃圾文字，长度判断失效，`孙悦` 没被正确处理）。

### 2. 其余改进（都是「更好用」的方向，不影响正确性）

| 项目 | 原版 | 本版 |
|---|---|---|
| 合并时的文件顺序 | 依赖文件系统返回顺序（macOS 上不保证） | **显式按序号排序**，保证页序正确 |
| 编译失败时 | 输出被丢进 `NUL`，完全看不到原因 | **显示错误摘要**（成功时仍然安静） |
| 编译卡死风险 | 无保护 | 加 `-interaction=nonstopmode` 且标准输入接 /dev/null，不会挂起 |
| tex 末尾缺行 | 抛异常，**整份报告生成失败** | 该字段留空并提示，其余照常 |
| 检查tex信息结果 | 只有纯文本报告 | 额外提供**校对表格**与 **JSON** |
| 合并书签 | 只能平铺 | 可选**嵌套** |
| 输入路径 | 只能手输/点浏览 | 支持**拖拽** |

### 3. 行尾（换行符）

原版在 Windows 上写文件时会自动把 `\n` 变成 `\r\n`（CRLF）。
本版**复刻了这个行为**，所以生成的 `信息检查*.txt` 和 `*.tex` 都是 CRLF，
方便和过去 Windows 生成的文件直接比对。

（内容本身与原版完全一致，只是换行符按原样保留。）

## 开发期的验收记录（与官方 Editorialbox 逐项比对）

这一节是**给维护者看的历史证据**，使用者不需要做任何比对。

「原版」同上：Windows 上那个 `工具箱.exe`（chenphilo 的 `Editorialbox`）。
开发时用「把原版 Python 字节码还原成可运行程序」的办法做了完全比对：

| 功能 | 比对结果 |
|---|---|
| 合并文件 | 13 个顶层书签落点**与原版完全一致**（cover→1、Meimei_Han→4、Lili_Zhao→20、Jie_Zhou→31、…、Lei_Li→156） |
| 检查tex信息 | **非作者字段完全一致**；作者行按第「四」节做了修复（实际测试 56 处差异全部是作者行） |
| 生成目录 | 结构、页码、标题、模板全部一致；作者行按同一处修复变干净（含 1/2/3 位作者、标题含破折号等边界情况均单独验证过） |
| 删除临时文件 | 8 个中间文件全部删除，14 个 tex / 30 个 pdf 未受影响 |
| 编译全部 | 2 篇文章 11 秒完成，PDF 正确重生（16 页 / 18 页） |

**2026-10-15 又补了一条更硬的证据**：把「合并」也搬进引擎（`Engine/mergepdf.py`）之后，
拿编辑用 mac 版合出来的真实成品比对同一期目录 —— **页数 176 = 176、
完整大纲 102 条逐条相同**（层级、名字、页码全同）。也就是说两个平台、两套实现，
输出是对得上的。

顺带发现：你那份旧的 `合并2026_10_03_22_56_39.pdf` 是 176 页，
而按当前源文件合并是 **175 页**。原因是 `Lei_Li.pdf` 从 21 页变成了 20 页
（旧文件的最后一个书签是 `cneditors[260113]左移.pdf`，那是旧版 PDF 自带的残留书签）。

### 重新构建

```bash
bash build.sh                        # mac：生成 dist/编辑部工具箱.app
cd sources-win && pwsh -File build-win.ps1   # Windows：生成两个 exe
bash tools/build_cli.sh              # mac：命令行版（仅合并/目录等，便于批量与回归）
```

**引擎的依赖**（只有直接跑命令行才需要；`.app` 与 Windows exe 都已打包好）：

```bash
cd Engine && python3 -m pip install --target vendor -r requirements.txt
```

命令行版用法：

```bash
toolbox-cli merge      <期目录> [--nested] [--editors]
toolbox-cli detect-editors <期目录>   # 只看识别到哪个编委页文件，不合并
toolbox-cli info       <期目录>
toolbox-cli content    <检查报告txt>
toolbox-cli compile    <期目录>
toolbox-cli deletetemp <期目录>
```

`--nested` 对应「嵌套书签」，`--editors` 对应「合并编委信息页」。
批量处理时可以先用 `detect-editors` 检查一遍各期的编委页能不能认出来。

## 已暂停 / 已移除的功能

**「快速bibtex」（单独一个标签页，把 Word 参考文献粘成 BibTeX）两个平台都没有独立入口。**

不过这件事**已经被「初排转换」覆盖**，而且做得更完整：初排转换会读 Word 文末的参考文献清单，
逐条解析成结构化字段（`slcn/docxsource.py`）、按本刊规范生成 `reference.bib`，
再往下还有「文献回读校验」与 AI 核实任务书。所以那个只做「文本转 BibTeX」的独立标签页
没有再造一个 —— 它会与引擎里已有的解析规则重复，两条路迟早给出不同结果。

**`.doc/.docx` 自动元数据识别（B2 方案）——已取消（GUI 入口撤下）。**

曾让「元数据文件」支持 `.docx` / `.doc`（`.doc` 由界面自动转临时 `.docx`）。用户真测**两例 Word 稿都没识别出元数据**，
2026-10-20 拍板回退：**取消自动识别，改为「填写元数据…」人工填写**（多作者/多单位，值直接进产物）。
**引擎的 `--metadata .docx` 能力保留**（CLI 高级兜底、GUI 不提供），`.doc → .docx` 的界面转换已删。

**「检查单字成行」——2026-10 已移除（两个平台都没有）。**

编辑部反馈**人工检查更准确、也更高效**，所以连标签页一起删掉了
（原 Windows 版和早期 macOS 版都有这个功能；它输出的 `check单字成行.txt`
只是一份报告，不影响稿件，可以随手删）。

代码本身还在 git 历史里（界面源码 `Features/SingleCheckFeature.swift`），
将来若想要回来，可以取回。

## 编委页历史调查记录

#### 关于「编委页」这一页的来龙去脉

顺便记录一下调查结论，免得以后又忘：

**工具箱从来没有合并过这一页。** 原来的合并规则只认 `扉页.pdf`、`000` 目录下的两个目录文件、
以及编号文件夹里的同名 pdf；`cneditors[260113]左移.pdf` 是散落在根目录的文件，
**不符合任何一条规则**，所以一直被跳过。

你以前的合并文件里之所以有它（在第 2 页），是**合并之后手工插进去的**。三条证据：

1. **页数正好差 1 页**：175（工具合并）vs 176（旧文件）
2. **书签集体指早了一页**：旧文件里 `Meimei_Han` 书签说第 4 页，
   但第 4 页实际是英文目录，文章真正在第 5 页 —— 从「Chinese Content」往后每个书签都偏早一页。
   这正是「合并完成后才插入一页」的典型特征：页面后移了，书签没跟着更新
3. **多出来一个来路不明的书签**：旧文件末尾那个 `cneditors[260113]左移.pdf` 书签，
   正是插入工具把该文件自带书签一起带进来的结果

现在勾上选项就能自动完成这一步，**而且书签位置是正确的**（旧手工版的书签是错位的）。
